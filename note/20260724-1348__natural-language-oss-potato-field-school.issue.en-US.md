## Issue title

`[Research] Can non-programmers experience OSS stewardship through potatoes and natural-language agents?`

## Background

OSS is often introduced as “code you can get for free.” It is also a knowledge ecosystem built from provenance, licenses, forks, differences, failures, issues, maintenance, human life, and the right to walk away.

OpenSourcePITETO makes one boundary obvious: a document can be forked, but a potato and a human body cannot. We can use that boundary to test whether non-programmers can experience the academic and cultural spirit of OSS through natural language.

“Spirit” is experiential, not a supernatural claim. It means sharing knowledge with provenance so another person can continue the investigation.

## Hypothesis

If a project provides a structured workspace, manifest, local `AGENTS.md`, note template, license, and Git history, a non-programmer may be able to use Codespaces, Copilot, Codex, or similar assistance to:

- read project scope and authority boundaries;
- separate facts, interpretations, hypotheses, inner experience, and unknowns;
- fork a recipe or note while preserving changes and sources;
- experience branches, diffs, commits, and issues through real work;
- compare reproduction costs with another OSS project;
- and separate supply from control.

## Participants

- Programming experience is not required.
- First-time Git, GitHub, and license users may participate.
- Age, food restrictions, publication consent, and account requirements need appropriate human handling.
- A participant should compare another OSS project only when they can responsibly observe it.

## Experiment A: documents only

- [ ] Read the Japanese or en-US README.
- [ ] Explain the workspace and project boundary in one sentence.
- [ ] Read `note/AGENTS.md` and create a note from the template.
- [ ] Separate at least one `[FACT]` from one `[HYPOTHESIS]`.
- [ ] Inspect a branch and diff.
- [ ] Draft a Japanese or locally appropriate commit message.
- [ ] Draft an issue or pull request.

## Experiment B: eat the potato

- [ ] Read the food and heat safety boundary.
- [ ] Cook the documented chips, or use a lawfully obtained bag of finished chips.
- [ ] Explain the difference between copying a recipe and reproducing its physical result.
- [ ] Record objective conditions separately from “good to me” or “not my preference.”
- [ ] Check that the AI did not write as if it personally tasted the chip.
- [ ] If cooking, return conditions, failures, taste, and unknowns in a note.

Eating store-bought chips is enough for the explanation experiment. Nobody must complete a hot-oil experiment to count as a participant.

## Experiment C: compare another OSS project

- [ ] Choose one OSS project you maintain, use, or can responsibly observe.
- [ ] Record benefits, copy cost, reproduction cost, invisible maintenance, and return routes.
- [ ] Record one similarity and one difference from OpenSourcePITETO.
- [ ] Check that project-specific pain was not silently generalized to all OSS.
- [ ] State what supply must not buy: merge power, ideological control, or permanent support.

## Experiment D: with and without an agent

Where practical, attempt the same small task under two conditions:

1. README and template only;
2. Codespaces plus Copilot, Codex, or similar natural-language assistance.

Compare:

- completion time;
- missing sources, licenses, or change descriptions;
- mixed facts and hypotheses;
- agent suggestions rejected or corrected by the human;
- participant understanding, fear, and enjoyment.

Do not promote a tiny, self-selected sample into a universal effectiveness claim.

## Acceptance conditions

- [ ] At least one person attempts the document-side sequence.
- [ ] Preserve the participant’s explanation in their own words.
- [ ] Record misunderstanding, agent error, and early exit with the same seriousness as success.
- [ ] If comparing another OSS project, preserve project differences.
- [ ] Separate claims ready for README promotion from hypotheses.
- [ ] Identify one workspace, manifest, or context-rule improvement for the next run.

Headcount is not the only measure of research value. A detailed failure from the first participant is still a valid receipt.

## Non-goals

- Transfer IP, legal, publication, or food-safety responsibility to an agent.
- Claim that “no programming required” means “no expertise required.”
- Find GitHub or any named company solely responsible.
- Use guilt to force users to pay.
- Turn a funny potato into page views while deleting the reproduction-cost problem.
- Generalize one successful run to every OSS project or non-programmer.

## Marketing-cannon candidate

> You do not have to write code to fork knowledge, preserve sources, and return a falsification to OSS research.
>
> Codespaces can fork the document. It cannot fork the potato or your body.
>
> AI can organize the recipe. Your mouth has to review the flavor.
>
> Turn both wheels—science and potato spirit. Eat a potato first.

This is a pre-test copy candidate, not an established advertising claim.
