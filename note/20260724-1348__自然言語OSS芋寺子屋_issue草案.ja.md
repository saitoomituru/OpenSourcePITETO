## Issue title

`[Research] 非プログラマは芋と自然言語agentでOSS知財管理・開発運用を体験できるか`

## 背景

OSSは「無料で取れるcode」として説明されやすい。しかし、出典、license、fork、差分、失敗、Issue、保守、生活、撤退可能性まで含む知識生態系でもある。

OpenSourcePITETOは、文書をforkできても芋と身体はforkできない。この分かりやすい境界を使い、非プログラマがOSSの学術性と精神性を自然言語で体験できるか検証する。

ここでいう精神性は、超自然claimではない。知識を囲わず、Provenanceを残し、他者が続きを掘れる形で渡す内面的・文化的experienceを指す。

## 仮説

構造化workspace、manifest、局所`AGENTS.md`、note template、license、Git履歴を先に用意すれば、非プログラマでもCodespaces、Copilot、Codex等の補助を使い、自然言語中心で次を体験できる。

- projectの範囲と責任境界を読む
- 事実、解釈、仮説、内観、unknownを分ける
- recipeまたはnoteをforkし、差分と出典を残す
- branch、diff、commit、Issueの意味を実作業で知る
- 自分の別OSSと再生産費を比較する
- 支援と支配権を分ける

## 対象参加者

- programming経験を参加条件にしない
- Git、GitHub、licenseの未経験者を含められる
- 未成年者、食品制限、公開同意、account作成等は別途適切なauthorityで確認する
- 他OSSとの比較は、そのprojectを責任を持って観測できる者だけが行う

## 実験A: 文書だけ

- [ ] 日本語またはen-US READMEを読む
- [ ] workspaceとmanifestが示すproject境界を一文で説明する
- [ ] `note/AGENTS.md`を読み、templateから自分のnoteを作る
- [ ] `[FACT]`と`[HYPOTHESIS]`を最低一つずつ分ける
- [ ] branchとdiffを確認する
- [ ] 日本語commit message案を作る
- [ ] Issueまたはpull requestの草案を作る

## 実験B: 芋を食う

- [ ] 食品・熱源の安全境界を読む
- [ ] READMEのポテチを実作する、または権利上問題のない既製ポテチを用意する
- [ ] 「recipeのcopy」と「物理的な再現費」の差を自分の言葉で説明する
- [ ] 客観記録と「自分にはうまい／好みではない」という主観reviewを別々に書く
- [ ] AIが味覚を代理したような文を書いていないか確認する
- [ ] 調理した場合は、条件、失敗、味覚、unknownをnoteへ返す

既製ポテチを食べるだけでも説明実験には参加できる。調理実験を完走しないことを失敗扱いしない。

## 実験C: 別OSSとの比較

- [ ] 自分が保守・利用・観測できるOSSを一つ選ぶ
- [ ] 便益、copy費、再生産費、見えない保守、還流routeを書く
- [ ] OpenSourcePITETOと同じ点・違う点を一つずつ書く
- [ ] project固有問題をOSS一般へ勝手に一般化していないか確認する
- [ ] Supplyがmerge権、思想支配、永続supportを買わない境界を書く

## 実験D: agentあり／なし比較

可能なら同じ小課題を二条件で行う。

1. READMEとtemplateだけ
2. Codespaces＋Copilot、Codex等の自然言語補助あり

比較するもの:

- 完了時間
- 出典・license・変更差分の欠落
- 事実と仮説の混線
- agent提案を人間が却下・修正した箇所
- 参加者が感じた理解、怖さ、面白さ

少人数・自己選択標本の結果を一般的効果へ昇格しない。

## 完了条件

- [ ] 少なくとも一人が文書側の一連を試す
- [ ] 参加者自身の言葉による説明を保存する
- [ ] 誤読、agent誤り、途中停止を成功例と同じ重さで記録する
- [ ] 他OSS比較を行う場合はproject差分を残す
- [ ] READMEへ昇格できるclaimと、まだ仮説のclaimを分ける
- [ ] 次回改善するworkspace／manifest／context規約を一つ特定する

人数は研究価値の唯一条件ではない。最初の一人の詳細な失敗も有効なreceiptとする。

## 非目標

- agentへ知財・法務・食品安全の責任を移す
- programming不要だから専門性も不要だと主張する
- GitHubまたは特定企業を単独原因と認定する
- 利用者へ罪悪感を与えて支払いを強制する
- 芋の面白さだけをPVへ変え、再生産問題を消す
- 一つの成功例から全OSS・全非プログラマへ一般化する

## マーケ砲candidate

> コードを書けなくても、知識をforkし、出典を残し、反証を返すOSS研究はできる。
>
> 文書はCodespacesでforkできる。芋と身体はforkできない。
>
> AIはrecipeを整理できる。うまいかどうかは、お前の口がreviewしろ。
>
> 科学とポテト・スピリットの両輪を回せ。とりあえず芋食え。
